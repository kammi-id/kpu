# 18: Penghapusan Akhir dan Tahap Selesai

**What to build:** Mulai 25 Januari 2027 00.00 WIB, seluruh situs memasuki Tahap Selesai. Setiap rute publik, akun, dan Admin hanya menampilkan "Proses penjaringan telah selesai dan data telah dihapus" beserta footer. Registrasi, login, onboarding, unduh Berkas Publik, dan seluruh API ditolak.

Cron pertama pada atau setelah waktu itu menjalankan Penghapusan Akhir tanpa konfirmasi. Seluruh objek R2 (`berkas/`, `ekspor/`, `publik/`) dan seluruh baris semua tabel, termasuk Peraturan dan audit, dihapus. Lalu tepat satu audit `hapus_data` beraktor `Sistem` disisipkan, dengan `keterangan` berisi jumlah baris per tabel dan jumlah objek R2 yang dihapus. Run berikutnya mengulang penghapusan sisa tanpa audit kedua.

Rujukan: [spec](../spec.md) bagian Tahap × kemampuan dan Ekspor Harian, Snapshot Pemeriksaan, Penghapusan Akhir.

**Blocked by:** 11, 16

**Status:** ready-for-human

- [ ] Run berikutnya tidak menambah audit, dan tetap menghapus sisa bila ada (acceptance 32).

- [ ] Penghapusan menangani daftar objek R2 berhalaman (lebih dari satu halaman listing).

## Comments

- Diimplementasikan 2026-09-15. `jalankanPenghapusanAkhir` (`src/worker/lib/penghapusanAkhir.ts`, baru) dipanggil dari `scheduled()` di `index.ts`, yang sekarang bercabang pada `tahapPada(scheduledTime)`: `Selesai` → Penghapusan Akhir, selain itu → Ekspor Harian (tidak berubah). Urutan: cek baris `hapus_data` beraktor Sistem yang sudah ada (idempotensi) → hitung jumlah baris tiap tabel aplikasi SEBELUM dihapus → hapus seluruh objek R2 di bawah `berkas/`, `ekspor/`, `publik/` (listing berpaginasi via cursor, parameter `ukuranHalamanR2` opsional khusus uji supaya multi-halaman dapat diuji tanpa membuat ribuan objek) → satu `DB.batch` menghapus seluruh baris tiap tabel, KECUALI baris `audit` yang merupakan penanda Sistem/`hapus_data` itu sendiri (`DELETE FROM "audit" WHERE NOT (aktor='Sistem' AND tindakan='hapus_data')`) → bila belum ada penanda sebelumnya, sisipkan tepat satu, `keterangan`-nya JSON berisi jumlah baris per tabel dan jumlah objek R2 yang dihapus.
- Keputusan implementasi non-trivial: baris audit `hapus_data` DIKECUALIKAN dari DELETE polos, bukan ikut dihapus lalu diperiksa "belum ada" pada tabel yang sudah kosong — pembacaan literal terakhir itu membuat penanda hilang-muncul bergantian tiap run (dihapus di run genap, disisipkan lagi di run ganjil karena tabel tampak kosong), gagal jadi bukti permanen bahwa Penghapusan Akhir sudah terjadi. Ditemukan lewat kegagalan uji "run berikutnya tidak menambah audit kedua" dan diperbaiki sebelum commit.
- Tahap Selesai menolak API yang sebelumnya belum bergerbang tahap sama sekali: unduh Berkas Publik (`GET /api/berkas-publik/:id`), `GET /api/peraturan`, dan `GET /api/unduhan` kini menolak dengan `{ error: "tahap_tertutup", tahap }` bila `!layananAktif(tahap)`. Rute publik lain (`/api/tahap`, `/api/konfigurasi-publik`) sengaja tidak digerbang — keduanya dibutuhkan agar shell klien bisa tahu tahap Selesai sedang berlaku. Registrasi, login, onboarding, dan seluruh API Admin/akun sudah tergerbang tahap dari tiket-tiket sebelumnya (02/03/06/14); tidak diubah di sini.
- Klien: `App.tsx` memuat tahap dari `/api/tahap` sekali di root; begitu `tahap === "Selesai"`, SELURUH rute (publik, `/akun/*`, `/admin/*`) diganti satu `SelesaiPage` (baru) yang menampilkan `PENJELASAN_TAHAP.Selesai` ("Proses penjaringan telah selesai dan data telah dihapus.") beserta `Footer`, tanpa memandang path — bukan penjagaan per rute.
- Uji seam Worker baru: `penghapusanAkhir.test.ts` (5 kasus: run pertama mengosongkan R2+semua tabel dan menyisakan tepat satu audit dengan `keterangan` berisi jumlah; run kedua tidak menambah audit dan tetap membersihkan sisa; listing R2 berhalaman lebih dari satu halaman; run tepat sebelum batas Selesai masih menjalankan Ekspor Harian dan tidak menghapus apa pun). Test lama di `ekspor.test.ts` yang mengasumsikan "tahap Selesai tidak menulis ekspor/terkini" (perilaku sementara sebelum tiket ini ada) ditulis ulang untuk mencerminkan bahwa Selesai kini benar-benar menjalankan Penghapusan Akhir, bukan sekadar diam. Tiga kasus baru di `peraturan.test.ts` menguji gerbang tahap pada ketiga rute publik yang baru digerbang.
- Walkthrough peramban sungguhan tidak mencakup tahap Selesai (jam sungguhan sekarang jauh sebelum 25 Jan 2027 dan App.tsx membaca tahap dari server, bukan jam disuntik); dibuktikan lewat 123 uji seam Worker dan pembacaan kode `App.tsx`/`SelesaiPage.tsx`. Ticket 17's alur (Penutupan Akun, Hapus data akun, Minta ditutup) sudah diverifikasi penuh lewat peramban sungguhan — lihat komentar tiket 17.
